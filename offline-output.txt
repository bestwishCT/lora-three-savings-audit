LoRA reading audit - offline arithmetic
Paper: Hu et al., LoRA: Low-Rank Adaptation of Large Language Models (arXiv:2106.09685v2).
All values below are arithmetic on numbers transcribed from the paper.
No model was trained, no GPU was used, no kernel was run.

== D1: three savings, three quantities  [P + A] ==
  training VRAM  1.2TB -> 350GB : reduction = 1.2/0.35 = 3.429x  [A]
  VRAM fraction remaining        : 350/1200 = 29.17%  [A]
  VRAM saved fraction            : 1 - 350/1200 = 0.708 (~2/3)  [A]
  checkpoint 350GB -> 35MB       : reduction = 350000/35 = 10000.0x  [A]
  => abstract 10,000x = checkpoint/trainable-params; 3x = training VRAM.  [P]

== D2: alpha/r scaling  [P + T] ==
  forward: h = W0 x + (alpha/r) * BA x   (Eq.3 plus alpha/r scaling)  [P]
  with alpha = r (the 'first r we try') the scale is r/r = 1.0  [T]
  A ~ Gaussian(0, sigma^2), B = 0  =>  BA = 0 at init  [P]

== D3: adapter latency table (GPT-2 medium, ms, RTX8000, 100 trials)  [P + A] ==
  Fine-Tune/LoRA     batch1=19.8 ms
  AdapterL           batch1=23.9 ms
  AdapterH           batch1=25.8 ms
  AdapterL vs baseline: 23.9/19.8 = 1.207  (+20.7%)  [A]
  AdapterH vs baseline: 25.8/19.8 = 1.303  (+30.3%)  [A]

== D4: subspace similarity  [P + A] ==
  Ar=8 vs Ar=64: top singular vectors overlap; dim-1 subspace with normalized similarity > 0.5  [P]
  => top direction carries the useful signal, rest ~ noise, so r=1 works well.  [P]
  NOT concluded: 'higher rank is always better'.  [P]

-- summary --
  Paper values (P): abstract, Eq.(3)+alpha/r, Table 1, Sec.4.2 VRAM/checkpoint, Sec.7.2 subspace.
  Arithmetic (A): ratios and percentages above.
  Teaching (T): alpha/r = 1 when alpha is set to the first r tried.
  NOT done: no GPU run, no kernel run, no training, no new experiment.
